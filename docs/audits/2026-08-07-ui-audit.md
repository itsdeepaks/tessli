# UI Audit — Tessli

**Audit date:** 2026-08-07  
**Auditor:** Antigravity (automated browser + source analysis)  
**Application:** Tessli — curated design-resource index

---

## Executive Verdict

Tessli has a solid editorial foundation with meaningful Browse, Collections, Saved, and Boards functionality. The design system is coherent, the accessibility baseline is decent, and no blocking runtime errors were observed. However, a significant product-direction misalignment exists on the homepage: resource cards link directly to external URLs rather than to the internal `/resources/[slug]` profile pages. This contradicts the canonical product decision ("internal source profile as the primary destination; Visit source is a separate action") and undermines the core value proposition of the research-index layer. This is the most important finding. Several supporting pages use placeholder content and several documented routes are not yet in primary navigation.

## Ship Readiness

**CONDITIONALLY READY** for a research-index demo stage, **NOT READY** for full product release.

**Reasoning:**

- The homepage card link model is wrong: it sends users directly to external sites, bypassing the internal profile pages that represent Tessli's core value.
- `/submit` and `/suggest` show placeholder screens with no functional forms — these appear in navigation and create false expectations.
- `/auth` exists as a visible route and appears navigable but has no working function — it should be hidden or removed from navigation.
- The Source Detail page (`/resources/[slug]`) is missing several sections documented in the product direction (best-for, capabilities, content objects, similar sources, collections containing source, etc.) — it only shows minimal Listed-level metadata for most sources.
- No 500/error boundary page is observable.

## Critical Findings (P1)

### F-01 · P1 · OBSERVED
**Category:** Information Architecture / User Journey  
**Route:** `/` (Homepage)  
**Viewport:** All  
**Problem:** Resource cards on the homepage link directly to external provider URLs (`href={resource.url}`) instead of to the internal Tessli source profile at `/resources/[slug]`. An `ExternalArrowIcon` is shown, which signals external navigation, and clicking a card opens the provider site in a new tab. This completely bypasses the internal research layer — the core product value — for users arriving on the homepage.  
**Expected:** Card primary action → `/resources/[slug]`; "Visit source" is a separate secondary action (as correctly implemented on `/resources`).  
**User impact:** Users cannot discover, read, or save source profiles via the homepage's most prominent interactive surface. The research-index layer is invisible to homepage visitors.  
**Evidence:** Source confirmed in `resource-card.tsx` L196–L203: `href={resource.url}`. Browse page (`browse-results.tsx` L85–L87) correctly uses `href={/resources/${profile.slug}}`. Homepage (`page.tsx` L60–L77) uses the `ResourceCard` component which has the external link model.  
**Likely source:** `web/components/resource-card/resource-card.tsx`, `web/app/page.tsx`  
**Recommendation:** Align homepage cards with the Browse card model — link the primary card to `/resources/[slug]` and add a "Visit source ↗" secondary action. Consider whether the homepage should use the `BrowseResults` card component directly, or create a lightweight homepage card that shares the same link model.

---

### F-02 · P1 · OBSERVED
**Category:** Missing functionality / Dead navigation  
**Route:** `/submit`, `/suggest`  
**Viewport:** All  
**Problem:** Both pages render styled placeholder screens explicitly stating the forms are not yet active. `/submit` says submissions will open after validation and moderation safeguards are implemented; `/suggest` says suggestion forms are inactive for this preview. However, these routes appear in the site footer navigation under a "Contribute" label, making them navigable destinations that deliver zero functionality.  
**Expected:** Either working forms, or no visible navigation links pointing to them, with a GitHub Issues link as an interim alternative as specified in AGENTS.md rule 19.  
**User impact:** Users who want to contribute or suggest improvements reach a dead end. Erodes trust.  
**Likely source:** `web/app/submit/page.tsx`, `web/app/suggest/page.tsx`, site footer component.  
**Recommendation:** Remove footer navigation links to `/submit` and `/suggest` until functional forms exist, or replace each page with an explicit redirect to a GitHub Issues template as stated in AGENTS.md rule 19.

---

### F-03 · P1 · OBSERVED
**Category:** Source Detail — Missing documented sections  
**Route:** `/resources/[slug]`  
**Viewport:** Desktop  
**Problem:** The Source Detail page only renders minimal Listed-level metadata: domain/URL, source type, access model, coverage status, and a short description. The product direction (Section 11) requires 15 sections including: best-for, not-ideal-for, capabilities, content objects, discovery model, platforms/frameworks, integrations/agent access, workflow fit, limitations/governance, evidence/freshness, similar sources, and collections containing the source. None of these richer sections appear on a typical Listed source detail page.  
**Expected:** Full profile rendering proportional to coverage level — at minimum: "Best for" and "Limitations" for Listed sources; complete enriched sections for Profiled/Verified sources.  
**User impact:** Users visiting `/resources/[slug]` from the Browse page receive barely more information than the card itself showed. The internal profile provides insufficient value to justify the navigation step.  
**Likely source:** `web/app/resources/[slug]/page.tsx`, `web/components/source-detail/`  
**Recommendation:** Implement the graduated profile display: minimum Listed sections visible for all; Profiled/Verified sections appear conditionally based on available data. Add "Similar Sources" as a core navigation mechanism.

## Complete Findings

### F-04 · P2 · OBSERVED
**Category:** Navigation / Hidden route  
**Route:** `/auth`  
**Problem:** The `/auth` route is live and renders a styled sign-in screen with a message stating "No sign-in request is sent from this page yet." Authentication is explicitly deferred. If any link to `/auth` exists in navigation or copy, it leads users to a non-functional stub.  
**Recommendation:** Audit navigation and all CTAs for any link to `/auth`. Remove or gate behind a dev-only feature flag.

---

### F-05 · P2 · OBSERVED
**Category:** Information Architecture — Missing CTA  
**Route:** `/` Homepage  
**Problem:** The homepage shows only a 12-item resource grid preview with cards linking to external URLs. There is no visible "Browse all N sources" CTA connecting visitors to the `/resources` Browse page. Users who click cards leave Tessli immediately. Users who don't click cards have no clear next action toward the full catalogue.  
**Likely source:** `web/app/page.tsx`, explore-results component  
**Recommendation:** Add a "Browse all N sources →" link/button beneath the homepage resource grid linking to `/resources`.

---

### F-06 · P2 · OBSERVED
**Category:** Forms / Interaction States  
**Route:** `/resources` Browse  
**Problem:** The filter controls require clicking a generic "Apply" submit button to take effect. No live/instant-filter interaction exists. The button label is generic and doesn't communicate what it applies.  
**Likely source:** `web/app/resources/page.tsx` L200  
**Recommendation:** Verify that pressing Enter in the search field submits the form. Consider `onchange`-triggered submit for selects. Relabel button to "Search" or "Filter results."

---

### F-07 · P2 · INFERRED
**Category:** Responsive  
**Route:** `/resources` Browse  
**Viewport:** Mobile  
**Problem:** Browse page has six filter controls that stack vertically on mobile, consuming significant screen space before results. No filter sheet/drawer is used despite the product direction specifying "filter controls wrap into two rows or move into a sheet."  
**Likely source:** `web/app/resources/page.tsx` L129–L201  
**Recommendation:** Implement a mobile filter sheet. Keep search visible; condense remaining filters into a "Filter (N active)" button that opens a modal sheet.

---

### F-08 · P2 · OBSERVED
**Category:** Accessibility — Save button label  
**Route:** `/resources` Browse (cards view)  
**Problem:** The Save button in `BrowseResults` card view (line 101–109 of `browse-results.tsx`) does not have an accessible `aria-label` identifying the resource by name — it only shows "Saved" / "Save" text. Multiple Save buttons on the same page are indistinguishable to screen readers.  
**Expected:** `aria-label="Save [Resource Name]"` on each save button.  
**Likely source:** `web/components/browse/browse-results.tsx` L101–L109  
**Recommendation:** Add `aria-label` that includes the resource name to the browse card save button.

---

### F-09 · P2 · OBSERVED
**Category:** Navigation — Missing Boards entry  
**Route:** Global header  
**Problem:** Primary navigation includes "Browse, Playbooks, For AI, Saved" but does not include "Boards" (`/boards`). Boards is a fully functional feature but has no navigation entry point.  
**Likely source:** `web/components/site-header/`  
**Recommendation:** Add "Boards" to navigation near "Saved", or group both under a "Workspace" dropdown.

### F-10 · P2 · OBSERVED
**Category:** Content / Missing context  
**Route:** `/boards`  
**Problem:** The Boards page shows no visible notice clarifying that boards are browser-local only and not synced to an account. Users may not understand this and could lose data unexpectedly.  
**Recommendation:** Add a compact inline notice stating browser-local scope, matching the notice pattern on `/saved`.

### F-11 · P2 · OBSERVED
**Category:** Content quality  
**Route:** `/resources/[slug]` Source Detail  
**Problem:** For Listed-level sources, description is short and there is no "Best for," "Limitations," or "Similar Sources" section. The page feels thin compared to what Browse-page users expect when clicking "Inspect Tessli profile →."  
**Recommendation:** See F-03. Additionally, implement "Similar Sources" via category-based filtering for all profile levels.

### F-12 · P3 · OBSERVED
**Category:** Visual Consistency — Dual card design  
**Route:** `/` Homepage vs `/resources` Browse  
**Problem:** Homepage and Browse page use visually distinct card designs for the same source entity. Homepage: media area, external arrow icon, tags, access badge, hover-only Save. Browse: minimal title/summary, explicit "Inspect Tessli profile →" CTA, always-visible footer actions. The product looks like two different tools.  
**Recommendation:** Align card anatomy across surfaces. Document the canonical card design in component contracts.

### F-13 · P3 · OBSERVED
**Category:** Accessibility — Hover-only interaction  
**Route:** `/` Homepage resource cards  
**Problem:** The Save bookmark button on homepage cards appears only on hover — not on keyboard focus or in touch. This violates the "no hover-only information" accessibility rule.  
**Likely source:** `web/components/resource-card/resource-card.module.css`  
**Recommendation:** Show save button on `:focus-within` the card at minimum. Make it always visible at touch/mobile widths.

### F-14 · P3 · OBSERVED

## Systemic / Root-Cause Issues

### 1. Dual card component model
**Affects:** F-01, F-12, F-13  
**Root cause:** Two card implementations — `ResourceCard` (external-link model, original) and the Browse inline card in `BrowseResults` (internal-link model, correct). Homepage still uses `ResourceCard`.  
**Fix:** Consolidate to one card with an `internalHref` prop. The Browse card model is correct.

### 2. Source Detail underbuilt
**Affects:** F-03, F-11  
**Root cause:** Detail page renders minimum viable template for Listed sources. Most of 295 sources are Listed, so most detail pages are thin.  
**Fix:** Implement graduated template with best-for, limitations, and similar sources for all coverage levels.

### 3. Non-functional routes in navigation
**Affects:** F-02, F-04  
**Root cause:** Routes deferred per product direction but still linked from footer navigation.  
**Fix:** Remove navigation links to deferred routes; add GitHub issue links as interim contribution path.

- **Boards** is a complete, useful local feature with goal input, source management, and Markdown export.
- **Collections/Playbooks** presents curated research paths with staged source sequences.
- **404 page** is styled on-brand with clear recovery actions.
- **Keyboard navigation** has a skip link and visible focus states.
- **Console health** is clean — no JavaScript errors across tested pages.
- **Design system** is visually coherent: warm palette, editorial typography, restrained orange, page grain — all consistent with `design.md`.
- **Mobile hamburger navigation** collapses correctly with a functional drawer.
- **Privacy/terms/about/curation** contain meaningful, truthful copy with no invented metrics or fake social proof.
